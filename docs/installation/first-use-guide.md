# 首次安装与配置：图形引导测试构建

本指南对应 `codex/research-product-improvement` 的安装体验改造及其成功的 CI Artifacts。
**已发布 v0.2.0-beta.1 仍是原控制台助手，没有本指南的新 Windows 图形向导。**
应用版本暂为 0.2.0；必须按 Artifact 的构建 SHA 区分新旧包，并同时下载同一运行的客户端与部署 ZIP。
真实 Windows 11 人工安装未执行，检查表见 [Windows 11 人工验收](windows-11-checklist.md)。

## 准备安装

Windows 11 x64 推荐 16 GB 内存、20 GB 以上空闲磁盘，论文与模型另需空间。
需要互联网、Docker Desktop 及其官方系统前置条件；这不是免依赖、离线安装包。
普通用户无需安装 Python、Node.js、Rust，也无需编辑 `.env`、Compose 或 Agent YAML。

1. 在 PR 的成功 Desktop 工作流页底部下载 Windows Artifact，解压外层 Artifact。
   其中含 MSI/EXE、`installer-manifest.json`、`build-metadata.json`、部署 ZIP 及其 `.sha256`。
   检查平台、版本、构建 SHA 一致。可用 Windows PowerShell `Get-FileHash 文件路径 -Algorithm SHA256`
   对照 manifest/校验文件。Artifact 需 GitHub 登录且有保留期限；失败运行的产物不是验收交付。
2. 按 [Docker 官方 Windows 安装指南](https://docs.docker.com/desktop/setup/install/windows-install/)
   安装 Docker Desktop，完成需要的管理员操作、虚拟化/WSL2 配置和重启。遵守 Docker 许可证条款。
   启动 Docker Desktop，等待运行就绪，使用 Linux containers。已有可用 Hyper-V/Linux 容器无需改用 WSL。
3. 双击 MSI 或安装 EXE，二选一。若缺少 WebView2，按安装器及 Microsoft 官方引导安装。
   测试版未签名：核对来源与校验值，遵循个人/组织安全策略，不关闭系统安全保护。
4. 将 `RAGSystem-deployment-windows-x86_64.zip` 中的 `RAGSystem` 文件夹完整解压到长期、个人可写位置，
   如 `C:\Users\你的用户名\RAGSystem`。不放 Program Files、共享盘或临时缓存；不要遗漏隐藏文件。

## 双击部署助手：五步初始化

双击部署目录的 `RAGSystem-Setup.exe`，进入统一图形入口。保留窗口等待操作完成，失败按窗口说明处理后点击同一按钮重试。
助手不会自动安装 Docker、强杀占用端口的程序或删除数据。

1. **检查安装条件**：点击检查。窗口识别 Docker 未安装/未运行、WSL 未就绪、Windows 容器模式、
   Compose 过旧、部署盘空间不足和 8000/8080 端口冲突。先按提示修复，再重新检查。
   空间检查只针对部署目录所在盘；Docker 虚拟磁盘和模型缓存空间还需在 Docker Desktop 检查。
2. **连接本机授权**：打开桌面客户端 → Connection authorization / 本机授权 → 复制配对哈希，粘贴到助手并保存。
   复制按钮不可用时可手动复制显示的哈希。这里不是模型 API Key；桌面实际凭据仍由 Windows Credential Manager 保存。
   已有配对可保留；更换需明确确认，旧客户端授权可能失效。回桌面点击“连接并检查授权”。
3. **安全保存密钥**：选择服务商，在遮蔽输入框填自己的 API Key 并保存。
   保存后清空输入框，只显示“存在”，不会回显密钥。已有密钥可保留；替换需确认。
   选择本地模型或稍后配置可跳过。其他 OpenAI 兼容服务在助手选择 OpenAI，使用 `OPENAI_API_KEY`。
   密钥保存在部署目录私有运行时文件，受 Windows ACL 限制；不能输入网页角色设置、写入报告或聊天。
4. **启动系统**：确认“启动可能恢复已有排队任务，其模型调用可能产生费用”，点击“启动 / 恢复系统”。
   首次通常 10–30 分钟，视网络/电脑而定。助手自动构建后端、启动数据库/Redis、执行数据库迁移、
   启动 API、三个 worker 和 Web，并检查就绪状态。启动本身不提交模型测试或新的推理任务。
   失败保留原数据，按固定错误码恢复后重试；不使用 Docker Clean/Purge/Delete volumes。
5. **开始使用**：回桌面连接授权，跟随首次使用引导的步骤进度和“下一步”。
   “基础服务就绪”仅表示基础设施正常，不等于模型可推理或科研答案正确。

以后先打开 Docker，再打开助手。识别到旧配置时可选“使用已有配置启动/恢复”，不会强制重复配对或重新输入密钥。
角色配置只读载入，快捷保存前也会确认，不自动覆盖高级用户的不同角色模型。
关闭桌面不会停止后台；助手“停止系统”保留所有数据。再次启动会继续使用同一项目的数据卷。

## 首次模型配置与主动测试

桌面首次使用“下一步”进入 Settings 的“首次模型配置”。

1. 选择服务商、账户实际可用的聊天模型和必要的 API 地址；预填名称只是参考，并不保证账户有权限。
2. 点击“为四个角色保存此配置”，核对确认弹窗后保存。Supervisor、Retriever、Analyst、Reviewer
   使用同一初始聊天模型；下方高级设置仍可逐角色修改。这里不修改 embedding/reranker 或已有索引。
3. 若刚在助手保存密钥，先在助手启动/恢复系统使容器读入，再点击“刷新配置与密钥状态”。
   刷新只读状态，不自动测试模型。
4. 按需点击“检查模型连接”或“测试实际推理”，阅读确认弹窗再开始。**外部请求须主动确认，可能产生费用。**
   连接检查读取服务商模型目录；部分兼容服务不支持目录请求，可明确选择单独推理测试。
   推理检查发送固定测试指令，不附带论文/对话；四角色不同模型时在高级设置分别测试。
   测试失败不会自动重试收费。页面重新打开不会自动测试，之前的测试结果也不伪装成当前结果。

| 状态 | 表示什么 | 下一步 |
| --- | --- | --- |
| 配置已保存 | 服务器已保存 provider/model/角色映射 | 检查密钥及账户模型权限 |
| 密钥存在 | 私有运行时变量存在，不证明有效 | 用户主动连接测试 |
| 连接检查成功 | 目录接口可响应，不证明能完成推理 | 用户主动推理测试 |
| 实际推理通过 | 当前固定指令得到期望结构 | 导入论文并逐例检查答案；不是科研质量认证 |

未出现在目录中的模型会提示，不直接认定可用/不可用。密钥被拒绝时在原生助手更换并启动生效；
模型无权限/不存在时修改名称或服务商；网络失败按组织代理/网络策略恢复，再主动重试。
不要把完整异常、API Key、环境文件或 Docker 日志粘贴到公开问题报告。

本地 Ollama 需要用户另行安装并加载适用模型。容器中 `localhost` 指向容器自己；Docker Desktop
可用宿主服务地址 `http://host.docker.internal:11434`，仅在本机可信范围配置访问，不开放公网。
Linux Engine 的宿主路由需按其网络配置处理，当前助手不自动配置 Ollama/host-gateway。
本地模型也有磁盘/算力/下载和许可证要求，未执行用户机器上的实际模型加载验收。

## 第一篇 PDF、问答与 Research

1. 跟随“下一步”打开 Knowledge Base，上传一篇自己有权使用的 PDF。
2. 查看导入/解析/索引状态，等待 `indexed`。默认本地 embedding/reranker 可能首次下载权重；
   基础服务就绪不代表这些权重已加载。网络或空间不足时按 [故障排查](troubleshooting.md) 恢复。
   不改模型维度去混用旧索引，不清理模型/论文/数据库卷。
3. 进入 RAG 提问，或切换 Research；真实模型调用可能收费。检查回答的引用、原文位置和证据。
4. 从结果导出报告。重新打开桌面、连接同一本地系统，可继续查看论文与历史对话。
   API、数据库或 worker 异常时保留历史，先查看 Diagnostics，再在助手启动/恢复。

## 升级、兼容入口与限制

- 升级保留原部署目录的 `.env`、`.runtime-secrets.env`、项目名和五类 Docker 数据卷。
  新 ZIP 先解压到临时位置，核对文件后按 [备份与升级](data-and-upgrades.md) 更新，不整目录覆盖私有文件。
- 备份/升级/空环境恢复/保留数据卸载暂使用成熟控制台入口：在部署目录运行
  `RAGSystem-Setup.exe --console`，按菜单操作，不需 Python/Node/Rust/Compose 开发命令。
  备份不含密钥，异机恢复要重新配对/输入密钥；卸载客户端和卸载容器都不静默删除数据卷。
- macOS ARM/Intel、Linux x64 保留原原生控制台助手和桌面安装路径，见 [平台教程](README.md)。
  新模型配置及步骤引导也适用于 Web；独立 Web 仍使用助手菜单 9 配对，不取消身份认证。
  Windows 图形助手没有扩展桌面 IPC，也没有新增本机 HTTP 管理服务。
- Docker 安装/WSL 重启、一次配对哈希复制、原生密钥输入和选择服务商仍需用户操作。
  普通首次初始化不需编辑配置文件；高级系统代理、扫描 PDF/OCR、Linux 宿主模型路由仍需额外配置。
- 工程端到端使用明确的 MOCK 模型；Windows 11 人工安装、用户真实密钥/模型、真实权重下载
  **NOT EXECUTED**，科研效果 **NOT MEASURED**。不自动开展付费测试；后续本地评测复用
  [现有评测工具](local-evaluation.md)。
