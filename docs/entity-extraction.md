# 实体候选与人工校正

知识库 → 展开论文“实体标注” → “生成实体候选与人工校正”。历史已索引论文同样适用。
先勾选候选需人工核对，再点击“生成或重试本地实体候选”。入库不会自动启动此工作。
处理采用既有 Run/outbox 与 ingestion worker，界面自动读取进行中的任务状态。
当前引擎 `source-labels-v1` 在本地执行，模型调用为 **0**，无需模型密钥或付费预算。

规则仅处理明确的 `Dataset:`、`Method:`、`Metric:` 标签，带引号的完整名称，以及紧邻
dataset/method/metric 类型词的保守大写标识符。含糊的多词裸名称、普通泛称、凭据样式内容跳过。
明确括号缩写可与名称记录同一来源候选组，两条记录仍需分别确认；不跨论文推断同义词。
单片段最多 100 条候选，最多 50,000 Unicode 字符；超大片段使任务失败，已提交批次保留。
规则覆盖有限，候选缺失不能证明原文不存在实体，规则正确率也未作为科研结果报告。

读取当前片段与候选后，原文只读。自动候选保存 chunk、原文摘要、精确 Unicode 字符跨度、
类型、版本、来源引擎和人工决定。候选默认“待确认”，不加入严格实体过滤索引。
确认后写入当前片段的实体链接。拒绝记录保留，重试不会自动复活它。
人工补充：在原文中选择连续的完整名称，选择类型，保存人工候选，然后单独确认。
人工修改：点击候选“修改”，重新选择原文与类型，保存后再次确认。
修改不改原始 PDF、原文、向量或 Evidence，也不全局改名其他论文中的同名实体。

处理全部候选后，核对整个片段的三类实体并勾选声明，才能标记审阅完成。
服务端检查所有候选页；当前页没有待确认记录仍不能绕过其他页的待确认候选。
审阅完成可以没有实体链接；这只记录人工审阅行为，不是科学实体不存在的证明。
旧实体链接保留可读，不能从没有跨度的旧记录推断已经核验。
“核对和移除当前实体链接”须明确确认，移除只作用当前片段，不删除共享实体或论文。

并发修改用候选版本检查，原文摘要变化后旧候选不能确认或校正。
旧候选可在核对当前原文后显式拒绝；页面会重新读取原文摘要。
超时或响应丢失先读回状态，不自动重放写入；读回失败时操作禁用。
同一论文的进行中任务复用，完成的同版本同原文任务也复用；新增片段可显式补提取。
失败历史保留，重试创建新的 Run，已经持久保存的候选依唯一来源跨度不重复。
论文退役会取消有关候选任务并级联移除其候选/审阅记录，迟到 worker 不得复活来源。

API 路径（需要本机授权；不存在任意远程目的地）：

- `POST /api/papers/{id}/annotation-runs`：指定本地引擎和明确候选审阅声明。
- `GET /api/papers/{id}/annotation-chunks`、`GET /api/papers/{id}/entity-mentions`：分页读取；候选可按 chunk UUID 过滤。
- `POST /api/papers/{id}/chunks/{chunk}/entity-mentions`：当前原文摘要与精确跨度。
- `PATCH /api/papers/{id}/entity-mentions/{mention}`：confirm/reject/correct，带期望版本和原文摘要。
- `POST /api/papers/{id}/chunks/{chunk}/annotation-review`：全类型人工审阅声明。
- `GET /api/papers/{id}/chunks/{chunk}/entities`、`DELETE .../entities/{entity}`：查看/显式移除局部链接。

旧手工标注 API 仍可使用，但新增名称必须逐字存在于当前原文；混合请求的无来源名称使整批回滚。
0012 迁移保留旧记录，增加来源候选和抽取版本。有候选或新流程审阅记录时拒绝有损降级。
本地 extractor 协议不允许网络模型；引入真实模型需要单独预算、使用记录和来源金标评测流程。
**真实模型抽取质量 NOT MEASURED**：用户尚未备妥真实论文、人工金标和获准模型预算。
自动化原文夹具标记 SYNTHETIC ONLY / NOT A BENCHMARK；浏览器 MOCK 不代表真实科研质量。
