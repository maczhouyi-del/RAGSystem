# 论文分组与自定义标签

在 Knowledge Base 展开“管理论文分组与标签”，创建项目分组或标签，并在单篇论文的“分组与标签”中勾选关联。一篇论文可以属于多个分组和多个标签；逐项增删关系，不用全量覆盖其他关联。勾选后的待确认状态会显示保存进度，服务器确认并重新读取后才显示完成；读取失败时禁用关联修改，先用“读取最新关联”恢复。

名称支持中文和 Unicode，最多 80 字符，拒绝空白、控制字符和可识别凭据。显示名按 NFC 保存；唯一键使用 NFKC + casefold，同类型不重复，分组与标签允许同名。重命名和删除带名称版本；陈旧版本返回 409，保留改名草稿并读取最新名称后由用户明确重试。删除需独立确认窗口，取消/Escape 不发写请求。

删除分组或标签只删除它及其关联，不删除论文、PDF、chunk、Embedding 或 Evidence。关联数是读取时的状态，名称版本不冻结成员集合；删除确认覆盖该项的当前全部关系。删除论文则由外键清理对应关联，保留标签及其他论文的关系。操作不触发 ingestion，也不修改论文的原始元数据或元数据版本。

## 检索范围

文献列表中选择分组和标签后点击“搜索文献”，对应 UUID 作为 `group`/`tag` 参数发送给服务器，并与标题、作者、年份、会议及索引状态取交集。结果总数和分页是服务器的结果，保持原有三条 SQL 预算。

RAG、Research 和显式约束记忆的“文献过滤条件”增加分组和标签多选。`group_ids`/`tag_ids` 每项最多 50 个 UUID，同字段取并集，不同字段与原有条件取交集。这些条件直接应用到 PostgreSQL dense 与 lexical 查询；模型规划不能放宽用户明确指定的范围，重试继续保留范围。约束记忆沿用原系统允许 ID 集合的交集语义；不把分组名称或关联视为科研 Evidence。

目录按 200 项分页读取，按需“加载更多”。已选但尚未加载/已删除的 ID 保留占位，绝不自动变成全库。删除的 ID、未知 ID、或把标签 ID 作为分组 ID 使用均返回空范围；用户必须明确清除或重新选择才能扩大范围。新建会话会清除上一会话的界面筛选。成员关系可变，检索读取当次数据库快照，不承诺整段研究运行冻结成员；历史 Run 的来源仍以其实际 Evidence 记录为准。

上传、导入、搜索、会话和科研 Evidence 保留原有架构。没有复制文献或向量，也没有新增持久化任务系统。

## API 和迁移

- `GET /api/collections?limit=200&offset=0`：带关联数的目录页。
- `POST /api/collections`：`{kind: "group" | "tag", name}`。
- `GET /api/collections/{uuid}`：最新名称/版本/关联数。
- `PATCH /api/collections/{uuid}`：`{name, expected_version}`。
- `DELETE /api/collections/{uuid}`：`{confirm_collection_id, expected_version}`。
- `GET /api/papers/{uuid}/collections`：论文当前全部组织关联。
- `PUT` / `DELETE /api/papers/{uuid}/collections/{uuid}`：幂等添加/移除一条关联。

以上沿用本机授权、错误码和请求追踪。桌面桥仅开放固定路径、UUID、对应 HTTP 方法和受限分页/搜索参数，不接受外部目标或任意 query。客户端 API 助手尊重显式的无请求体 PUT/DELETE，同时保留未指定方法时的 GET/POST 默认行为。

迁移 `0010` 增加组织表及具有双向级联外键、复合主键和反向查询索引的多对多表，既有文献保持不变。真实 PostgreSQL 测试验证升级、模型一致性、降级与重升；存在组织记录时拒绝有损降级，须先另行备份和明确处理组织数据。不要绕过保护。大库性能及索引构建时长尚未测量。

## 验证边界

真实 PostgreSQL 覆盖多重关联/唯一关系、并发重复关联、乐观改名冲突、删除文献/分组的隔离、原始 PDF/元数据保留、dense/lexical OR/AND 范围以及 Evidence 的 ID、偏移、精确内容与分数保留。图测试使用离线脚本模型验证规划范围不放宽；浏览器使用明确 MOCK HTTP，验证管理、恢复、目录分页和两种模式请求。它们不证明科研准确性。
