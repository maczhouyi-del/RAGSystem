# 批量 PDF 导入

在 Knowledge Base 的 PDF 表单多选或拖拽文件，检查共享作者、年份和会议信息，然后点击“上传并建立索引”。单篇支持自定义标题；多篇使用各自文件名，后续可逐篇编辑元数据。每次选择和等待上传最多 100 个文件，每个最多 30 MiB，同时上传最多两篇。

文件选择仅保存浏览器 File 引用；只检查五字节 PDF 前缀，不预读整批文件。Web 使用现有 multipart 请求；桌面桥仅为当前上传请求生成既有 multipart/base64 数据。没有另建服务器任务系统，也没有测量实际峰值内存；桌面编码仍有单个请求的额外内存开销。

## 状态与恢复

上传回执仍是原有 Run 响应，另增 `paper_id` 和严格布尔 `reused_existing`。复用结果来自服务端 PDF 内容 SHA 去重，不使用文件名或客户端模拟哈希。相同 PDF 返回已有文献与导入任务，保留人工元数据修改。上传接受与索引完成分别展示；每篇保留独立失败原因和操作，其他文件继续处理。

上传失败后，手动“核对并重试此文件上传”发送原始文件；丢失响应时明确显示结果待核对。重复内容在服务器收敛，不自动重放写请求。解析/索引失败使用原有论文 retry 接口，不重新上传 PDF；同一文献已有 queued/running ingestion Run 时复用它，原失败 Run 保留。并发重试通过现有论文锁与事务防止创建第二个待执行任务。状态不允许重试时仍返回原有 409。

详情 GET 和元数据 PATCH 响应增加只读 `latest_ingestion_run_id`，用于重试响应丢失后的读取恢复。列表/搜索该字段默认空，不增加每篇查询，保留分页的三条 SQL 预算；需要任务状态时查询单篇详情。最新任务查询没有新增索引，较大 Run 历史下的性能未测量。

本地最多保存最近 50 个文献/Run UUID，用于刷新后的只读状态查询。不会保存文件内容、文件名、元数据、授权或待上传队列。离开页面后未提交文件需重新选择；已经接受的后台任务继续执行。状态读取使用有超时的单篇 Paper 和 Run 请求，后台批次最多四个读取 worker；上传接受后也立即读取该篇。页面可见时五秒刷新待处理项，恢复焦点/联网时读取，另有手动刷新。删除的来源显示不可用。

查看索引结果显示服务器文献状态、chunk 数、Run ID 与错误码，并提供原始 PDF 入口。此处的“已索引”是工程任务状态，不代表实体标注完整、回答正确或科研结论已验证。

## 验证边界

真实 PostgreSQL 集成测试验证上传去重、实际回执、并发上传与重试只创建一个新 Run/outbox，以及既有元数据和删除事务保护。浏览器测试使用明确 MOCK HTTP 状态，覆盖两条上传并发、多文件独立失败、上传和重试响应丢失、刷新恢复、重复内容、单篇元数据兼容与拖拽前不写请求。它们不证明真实 PDF 解析质量或模型科研效果。
