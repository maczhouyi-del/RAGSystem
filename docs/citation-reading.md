# 引用核查与 PDF 阅读

点击回答中的引用，系统重新读取对应 Run，核对当前来源是否可用，再显示论文、冻结版本、
章节、页码、Evidence/Chunk ID 和完整检索原文。来源退役后不显示缓存原文，也不能继续打开引用。
不同引用使用各自的论文 ID；不会用当前会话的第一篇论文代替其他引用。

“打开原始 PDF”位于面板上方。Web 打开受保护的本机 `/api/papers/{id}/pdf`，已知页码通过
`#page=N` 请求浏览器阅读器定位。Desktop 使用现有 UUID/固定路由白名单 IPC，在 Rust 中
读取经过授权的本机 PDF，检查文件类型/体积，写入私有随机命名缓存，再调用系统阅读器。
系统阅读器可能忽略页码，面板明确给出手动跳页提示。缓存生命周期沿用现有受限实现。

页码未知时，按钮和章节说明显示“页码未知”，打开完整 PDF 时不添加假 `#page=1`。
`page_location` 同时进入轻量引用元数据、实体关联列表、审阅片段列表和只读来源面板，
防止 TASK-12 的数值兼容占位值被误当真实第一页。旧索引缺少该新字段时保留原有已存页码。

候选页优先使用实际来源区域中的页码，多个表格区域分别提供入口。没有区域时，使用已存
页码范围降级，入口数量有界；表题、表头等辅助上下文保留独立来源 ID、页码和原文。
损坏或越界区域被忽略，不能凭缓存中的 `pdf_location=available` 声明制造高亮。
有可验证的 PDF SHA256 时可展开核对摘要；缺失/损坏的可选摘要不会挡住旧来源原文。

原文面板可标记 Reviewer 通过后的逐结论支持片段：验证完整 quote 与原始 content 的
Unicode code-point 跨度一致，再核对支持跨度位于该 quote 内。重叠支持跨度合并显示，
原文字符及数字不会改变。RAG 与 Research 分别使用自己的有效引用验证结果；缺字段、
未通过验证、越界跨度、原文不一致时保留完整原文，不标记支持片段。
这些标记作用于原文面板，**不代表 PDF 中逐字高亮或人工认定科研事实正确**。

TASK-12 的 bbox 是元素区域，不是逐字坐标。当前选择已有外部阅读器与原文核查方式：
没有新增 PDF.js/解析 worker 依赖、模型下载或调用；没有修改 Tauri CSP、文件权限、
远程 WebView 允许范围或本机 API 授权设置。嵌入阅读器需要单独评估锁定版本的许可证、
解析安全与 worker/包体成本，并建立可靠字符到 PDF 坐标映射，之后才可声称逐字 PDF 高亮。

验收区分实际 PG/API 原始文件读取、MOCK 浏览器/IPC 操作与真实原生构建检查。
系统阅读器的人工操作和页码支持依平台而定，本轮 Windows 11 人工阅读验收 NOT EXECUTED；
标准 Docling 布局/OCR 正确率及科研质量 NOT MEASURED。
