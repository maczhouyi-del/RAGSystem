# 实体标注覆盖与严格过滤

在文献库打开每篇论文的“实体标注”面板，读取当前状态、审阅覆盖和已有实体关联。
此读取按需执行，不把入库完成误当成标注完成；未读取或读取失败时明确显示状态未知。
数据集、方法、指标按片段关联显示，每页最多 50 条，可翻页并按需查看原始来源片段、章节及页码。
关闭面板会撤销正在读取的详情，迟到响应不能重新显示来源。

状态规则：

- 未处理：没有当前审阅或实体链接；也包括没有解析片段的论文，不能证明没有实体。
- 处理中：存在针对当前原文的 queued/processing 审阅记录。
- 失败：没有处理中记录，但有当前原文的 failed 记录；已有成功部分保留。
- 部分完成：有已完成审阅或历史实体链接，尚未明确审阅全部片段。
- 完成：至少一个片段且全部片段均有 completed 审阅记录，原文 SHA256 与记录一致。

完成仅表示数据集、方法、指标三类的审阅覆盖，不能证明提取准确或原文实体穷尽。
历史人工添加的 ChunkEntity 链接不会自动生成 completed 记录；没有链接也不会自动证明审阅完成。
TASK-10 只提供状态契约、持久化覆盖记录和只读界面，不启动抽取或付费模型调用；TASK-11 接入真实抽取与人工审阅写入。
原文变化使旧审阅摘要失效，重新解析产生的片段不会继承旧审阅记录。
历史链接没有精确实体跨度，来源窗口明确提示名称尚未由该链接证明。

## 严格实体过滤与普通文本检索

RAG、Research 与显式条件记忆中的 datasets/methods/metrics/entity_types 是已有实体链接上的精确谓词。
名称忽略大小写；同字段 OR、不同字段 AND，与论文 ID、分组、标签、作者、年份、期刊、章节范围共同生效。
它们不做全文替代、不做别名猜测、不把未标注当作不存在。
普通问题文本由既有 dense/lexical 检索处理；论文库 title 搜索仍是标题搜索。

输入实体条件后，界面用只读 POST 查询当前范围的可检索片段数、明确审阅数、链接覆盖及严格匹配数。
查询在一个 PostgreSQL statement snapshot 中计算范围与匹配，沿用同一 apply_filters，排除非 indexed、withdrawn/retracted 来源。
这是条件覆盖检查，不是某个问题的检索召回保证，也不验证 Embedding 兼容性、模型效果或最新会话记忆的最终交集。
状态查询失败/超时不放宽过滤条件；新会话仍按原逻辑明确清空条件。
零匹配时说明条件当前不可满足，允许用户明确清除条件后再做普通文本检索；部分标注时即使有匹配也提示结果不完整。
覆盖查询不加载模型或创建 Run；信息按读取快照显示，后台更新后需要刷新。

## 接口与持久化

- GET `/api/papers/{uuid}/annotations?limit=50&offset=0`：状态、审阅计数和分页实体关联；limit 1–200、offset 0–1,000,000，未知/重复参数拒绝。
- GET `/api/papers/{uuid}/chunks/{uuid}/source`：只读当前同论文原文；不存在/删除分别遵循既有 404/410。
- POST `/api/annotations/coverage`：只读 MetadataFilter，未知字段拒绝，无模型调用、写入或第二队列。

0011 添加 chunk_annotation_reviews，一片段一记录、显式状态和原文摘要，可关联既有 Run。
删除片段级联移除审阅，删除 Run 只清空指针；不复制 PDF/向量/证据。
非空审阅表阻止 downgrade，必须先明确处理记录；不会静默丢失审阅覆盖。
不会从 parser 任意 metadata 读取“已完成”。写入者必须只有在全部三类审阅完成时标记 completed，不能把 failed/取消转成功。

大语料状态查询需要读取原文计算摘要，延迟与内存未测量。没有真实论文人工金标或科研准确率结果。
自动化语料是 SYNTHETIC ONLY / NOT A BENCHMARK，浏览器 HTTP 是 MOCK；真实 PostgreSQL 与真实 dense/lexical 条件验证单独记录。
